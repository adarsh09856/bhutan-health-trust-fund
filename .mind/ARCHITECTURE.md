## Key Conventions

### Routing (TanStack Router)

- File-based routing in `src/routes/` — route files map 1:1 to URL segments
- Dynamic segments use `$param` naming (e.g., `$slug.tsx`)
- **Do NOT edit `routeTree.gen.ts` manually** — regenerated by `vite dev`/`vite build`
- Route loaders use `createFileRoute` with `loader` function for data fetching
- Admin routes check session via `verifyCurrentSession` in their loader — redirect to `/admin/login` if unauthenticated

### API Layer (Server Functions)

- All data access goes through server functions in `src/lib/api/`
- Server functions are imported directly into route loaders/actions — no REST endpoints
- Zod validates all user inputs before DB writes
- All mutations return typed responses; errors surface as structured objects, not thrown exceptions

### Database (Drizzle ORM)

- Schema defined in `src/lib/db/schema.ts` — single source of truth
- Migrations generated with `drizzle-kit generate` and applied with `drizzle-kit migrate`
- The `db/index.ts` export auto-detects if PostgreSQL is available; falls back to in-memory store
- Use Drizzle query builder — no raw SQL strings in application code

### TypeScript

- Strict TypeScript throughout — `"strict": true` in tsconfig
- All server functions have explicit return types
- Route params and search params have typed schemas via TanStack Router

### Styling (Tailwind CSS v4)

- OKLCH colour tokens defined in `src/styles.css`
- No inline styles — Tailwind utility classes only
- Radix UI primitives styled via Tailwind className prop
- Sonner toasts for all user-facing success/error feedback

### Forms

- React Hook Form + Zod resolver for all forms
- Validation errors shown inline (never alert())
- Submit buttons disabled during pending state

## Admin Authentication Flow

1. User submits email/password at `/admin/login`
2. `adminLogin` server function verifies bcrypt hash
3. On success: signed JWT stored as httpOnly cookie + session token
4. All admin routes call `verifyCurrentSession` in their loader
5. Failed verification redirects to `/admin/login`
6. Roles (`SUPER_ADMIN`, `ADMIN`, `EDITOR`) gate specific admin actions

## Donation Reference Format

```
BHTF-DON-XXXXXX   where XXXXXX is a zero-padded 6-digit sequential integer
Example: BHTF-DON-000042
```

Reference numbers are generated server-side at pledge submission time.
They are globally unique and immutable once issued.

## Inquiry Status Workflow

```
UNREAD → IN_PROGRESS → REPLIED → ARCHIVED
```

Status transitions are one-directional. Secretariat staff add internal resolution notes at any stage.
