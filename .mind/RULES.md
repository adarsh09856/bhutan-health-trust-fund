## STEP 3 — Implementation Rules (Non-Negotiable)

### Stack rules — never violate

- Framework: **TanStack Start (SSR) + TanStack Router + TanStack Query** — no Next.js, no Remix
- Build: **Vite 7 + Nitro** — do not swap build tooling
- Database: **PostgreSQL + Drizzle ORM** — no raw SQL strings, no other ORM
- Auth: **`jose` JWT + bcryptjs** — do not introduce Passport or NextAuth
- UI: **Radix UI + Tailwind CSS v4** — do not add a second component library
- Forms: **React Hook Form + Zod** — do not add Formik or yup
- Toasts: **Sonner** — never use `alert()` or `window.confirm()`
- Charts: **Recharts** — do not add Chart.js or D3
- Language: **TypeScript strict** — `npx tsc --noEmit` must pass with 0 errors

### Routing rules

- File-based routing in `src/routes/` — one file per URL segment
- Dynamic segments: `$param.tsx` naming convention
- **Never edit `routeTree.gen.ts` manually** — auto-generated by Vite plugin
- All admin routes MUST call `verifyCurrentSession` in their loader and redirect to `/admin/login` if unauthenticated

### Data & API rules

- All data access goes through server functions in `src/lib/api/`
- No REST endpoint files — server functions are imported directly into route loaders
- All user inputs validated with Zod before any DB write
- All mutations return typed structured responses — never throw unhandled exceptions to the client
- Use Drizzle query builder exclusively — no raw SQL strings in application code

### Security rules

- Never hardcode credentials, passwords, or secrets in any file
- Never expose raw DB error messages to the client
- Admin authentication always verified server-side in route loaders
- Donation reference numbers (`BHTF-DON-XXXXXX`) are immutable once issued — never delete
- Inquiry status transitions are one-directional: `UNREAD → IN_PROGRESS → REPLIED → ARCHIVED`

### In-memory fallback

- The `src/lib/db/index.ts` layer auto-falls back to in-memory seed store if PostgreSQL is unavailable
- **Do not remove or disable this fallback** — it is required for offline demos

## Project-Specific Hard Rules

These rules are absolute. No exceptions:

1. **Never mention external code hosting platforms** in any public text, system logs, or user-visible output.
2. **Never commit `.md` or `.pdf` files to git** — hard project rule.
3. **Donation references are immutable** — `BHTF-DON-XXXXXX` cannot be changed or deleted once issued.
4. **No REST endpoints** — all data flows through TanStack server functions.
5. **Never edit `routeTree.gen.ts`** — it is auto-generated.
6. **TypeScript strict** — 0 errors required at all times.
7. **In-memory fallback must remain** — do not remove the offline demo capability.
8. **Radix UI is the only component library** — do not install shadcn/ui, MUI, or any other.
9. **All admin routes verify session server-side** — never trust client-only auth state.
10. **CSV export must be maintained** for donations and subscribers tables — preserve this for any new manageable data tables.
11. **Sonner toasts only** for user feedback — no browser alerts, confirms, or prompts.
